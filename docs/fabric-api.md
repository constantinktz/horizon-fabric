# Fabric API on Horizon's native mods

What each module of Fabric API 0.162.0+26.3 gives a Java mod, and what a Horizon native mod (Rust) uses instead.
Fabric's public `api/` packages are the reference; Horizon's side is the hook catalog (`native-hooks.json`,
`tools/native-hook-fragments/`), the hook points in `crates/horizon-client/src/game/native_hooks.rs` and the
helpers beside them ([native-mods.md](native-mods.md)), and content mods' data files ([mods.md](mods.md)).
The six modules that cross the network are Horizon's client speaking Fabric's protocol to a Fabric server
([fabric-servers.md](fabric-servers.md)); they are listed here for completeness only.

A hook named `native_x` below is `Game::native_x` in `native_hooks.rs` unless another file is given; a mod
implements it as `Hooks::x` from `horizon_client::mod_api`. Hooks that only a fragment lists yet (no API
number) are marked *pending*.

Status: **covered** (a Fabric mod's use of the module has a native equivalent), **partial** (the common
part is covered, the rest is named), **missing**, **n/a** (build-time, test-time or Java-only: nothing a
native mod needs), **network** (ported by the Fabric protocol work, not a native-mod API).

## Summary

| Status | Modules |
|---|---|
| covered | 6: entity-events, events-interaction, lifecycle-events, loot, message, screen |
| partial | 22: advancement, lookup, biome, block, block-getter, command, content-registries, convention-tags, creative-tab, game-rule, item, key-mapping, model-loading, object-builder, permission, rendering, resource-conditions, resource-loader (v1 and the deprecated v0), sound, tag, transfer |
| missing | 4: debug, dimensions, renderer, rendering-fluids |
| n/a | 8: api-base, client-gametest, crash-report-info, data-generation, gametest, renderer-indigo, serialization, transitive-access-wideners |
| network | 6: data-attachment, menu, networking, particles, recipe, registry-sync |

That is 46 rows: the 45 top-level modules and `deprecated/fabric-resource-loader-v0`.

## Added with this page

- `client_lifecycle` (*pending*): `native_client_started`, `native_client_stopping`, `native_client_tick_pre`,
  `native_client_tick_post`, gated once-only and paired by `NativeLifecycle` in `game/native_lifecycle.rs`
  (`native_lifecycle_client_tick_start`, `native_lifecycle_client_tick_end`, `native_lifecycle_client_stopping`).
  Called from the window's tick loop in `game.rs`, `shut_down` and `begin_closing_save` (`game/saving.rs`).
- `client_chunks` (*pending*): `native_client_chunk_load` (end of `remote_chunk`, `game/remote_chunks.rs`) and
  `native_client_chunk_unload` (`native_client_chunks_unloading`, from `forget_remote_columns` in
  `game/remote.rs`, only for columns the level holds).
